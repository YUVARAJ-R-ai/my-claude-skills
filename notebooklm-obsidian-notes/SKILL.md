# NotebookLM to Obsidian Exam Notes

Transform raw study outputs generated by Google NotebookLM or Gemini into structured, exam-ready notes inside the Obsidian vault (`obsidian_valt/`).

## Why this exists

NotebookLM is an exceptional tool for RAG-based course synthesis across dozens of lecture PDFs and past papers. However, copying output into Obsidian presents specific friction points:
1. **ASCII Art vs. Mermaid:** NotebookLM frequently outputs text-based ASCII box art (`+---+`, `| |`) which breaks on mobile, lacks interactive zoom, and looks unpolished in Obsidian.
2. **Citation Detachment:** NotebookLM's inline citations need to map to exact local filenames and page numbers (e.g., `[[Module-3_PPT.pdf#page=60]]`) so the `pdf-plus` plugin can open and preview them in split view.
3. **Graph Isolation:** Raw pastes lack YAML frontmatter, tags, callouts, and connections to the subject's Map of Content (MOC), preventing the Obsidian Knowledge Graph from forming meaningful clusters.

This skill standardizes the ingestion, formatting, and linking process.

## Workflow Steps

### 1. Identify Subject & Context
- Determine the target course folder in `obsidian_valt/` (e.g., `SE/`, `DAA/`, `DMGT/`, `CAD/`, `ES/`, `Micro/`, `STS/`).
- Determine the module number, exam scope (CAT-1, CAT-2, FAT), and the descriptive note title.
- If not provided in the paste, infer them from the content or ask concisely.

### 2. Modernize Diagrams (ASCII to Mermaid)
Scan the content for ASCII text diagrams (boxes made with `+---+`, `|`, `-->`, `^`, `v`). Convert each into a clean, valid Mermaid diagram:
- **System Perspectives / Hierarchies:** Use `flowchart TD` or `flowchart LR`.
- **System Context Models & Interfaces:** Use `flowchart LR` or `flowchart TD` with subgraphs for external systems.
- **Level 0 Data Flow Diagrams (DFDs):**
  - Central system as a circle/node: `SYS(("<b>0.0</b><br/>SYSTEM NAME"))`
  - External entities in a subgraph or rectangular nodes: `ENTITY["Actor / Sensor"]`
  - Directional data flows labeled clearly: `ENTITY -- "Input Data" --> SYS`
- **Sequences / Protocols:** Use `sequenceDiagram`.
- **State Machines / Event Responses:** Use `stateDiagram-v2`.

### 3. Verify and Format PDF Citations
- Format all citations as Obsidian wikilinks: `[[filename.pdf#page=N]]` or `[[filename.pdf#page=N|Display Label]]`.
- Verify that the referenced PDF exists in the course's `_sources/` directory (`slides/` or `pyqs/`).
- If an exact page number is present, preserve it. If a citation references a past paper (e.g. `BCSE301L_CAT2_25-26_E1.pdf`), ensure it links with `#page=N` if known.

### 4. Apply Obsidian Visual Structure
- **YAML Frontmatter:**
  ```yaml
  ---
  course: <CODE, e.g. BCSE301L>
  subject: <Subject Name>
  module: <Module Number>
  exam: <CAT-1 | CAT-2 | FAT>
  type: notebookllm-synthesis
  tags:
    - <Subject>
    - <Exam>
    - Module<N>
    - <Specific-Topic>
  created: YYYY-MM-DD
  ---
  ```
- **Callouts:**
  - Wrap high-yield summaries in `> [!abstract] High-Yield Summary`
  - Wrap real-world analogies in `> [!tip] Real-World Analogy`
  - Wrap past exam questions in `> [!question] Past Paper Question (Marks)`
  - Wrap worked solutions or problem-solving steps in `> [!example] Step-by-Step Solution`
- **Headings & Numbering:** Ensure standard H1 (`#`) for title, H2 (`##`) for major sections, H3 (`###`) for subsections.

### 5. Cross-Link to Knowledge Graph & MOC
At the bottom of the note, add navigation and graph connections:
```markdown
---
## 🔗 Related Notes
- [[<SUBJECT>_CAT2_MOC]] — Master Dashboard
- [[<SUBJECT>_Master_Notes]] — Comprehensive Exam Skeletons
```
If the subject has a master Map of Content (like `SE_CAT2_MOC.md`), ensure the new note is indexed or visible via the Dataview query.

### 6. Save Note
Save the formatted markdown file directly into:
`/home/yuvaraj/Drive1/college/Sem 5/obsidian_valt/<SUBJECT>/<Note_Title>.md`

## NotebookLM Prompting Reference

When prompting NotebookLM to generate content that requires minimal post-processing, use this output contract:

```markdown
[OUTPUT FORMATTING CONTRACT - OBSIDIAN STRICT]
1. CITATIONS: Format all citations strictly as Obsidian wikilinks matching exact uploaded source PDFs and page numbers: [[filename.pdf#page=N]].
2. DIAGRAMS: NEVER use ASCII art or text boxes (+---+). Always output all diagrams, flowcharts, architectures, and DFDs inside Mermaid code blocks (```mermaid ... ```).
3. CALLOUTS: Use Obsidian callout syntax:
   - `> [!abstract] High-Yield Summary` for core summaries
   - `> [!tip] Analogy` for analogies
   - `> [!question] PYQ Question` for previous year questions
4. SKELETON ANSWERS: For exam questions, provide a point-by-point skeleton answer formatted for writing under time pressure.
```

## Automation Helper (`save-note`)

The vault includes a CLI helper script at `/home/yuvaraj/.local/bin/save-note`.
- **Usage:** `save-note <SUBJECT> [OPTIONAL_TITLE]`
- Reads from `wl-paste` (Wayland clipboard), automatically adds frontmatter, wraps loose ASCII in codeblocks, and saves directly to `obsidian_valt/<SUBJECT>/`.
